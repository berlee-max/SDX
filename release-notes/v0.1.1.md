# AI Agent SDX v0.1.1

首个版本装上去之后暴露的问题,都是同一类:**改名只改了看得见的一半**。

## 修复

**全新安装的默认用户名还是上游的。** 装完打开,个人资料显示 `cc-haha`,下面挂着
`github.com/NanmiCoder/cc-haha`。桌面端自己的默认值早就对了,但它只是服务端没响应时的兜底——
真正生效的是服务端那一份,而它没被改到。

这条能漏掉,是因为之前的审计只 grep 了打包后的 `app.asar`,零命中就收工了。应用其实出
**两个包**:`app.asar` 来自 `desktop/`,还有一个 77MB 的 sidecar 由 `bun build --compile` 从
`src/` 编出来。默认用户名在后者里,而它从没被扫过。

同一次排查还找出三条用户真会读到的文案,全在 sidecar 里:Agent Teams 的设置项描述、
诊断包的 README、以及诊断报告的标题。

**对外的 User-Agent 不再冒充上游项目。** 三处,发给第三方服务器:

| 去向 | 之前 | 现在 |
| --- | --- | --- |
| opencode.ai | `cc-haha/$VERSION` | `sdx/$VERSION` |
| Grok OAuth | `cc-haha-grok-oauth/1.0` | `sdx-grok-oauth/1.0` |
| IM 适配器取远程图片 | `claude-code-haha-im-adapter` | `sdx-im-adapter` |

第三条是 dump 成品二进制里全部 UA 才发现的,在 grep 源码已经"查干净"之后。**出货的是二进制,
该问的也是它。**

`Claude-User`、`claude-cli/…`、`Claude-Code-Plugin-Manager` 保留:它们标识的是被包装的引擎,
而且 Anthropic 的接口会按 `claude-cli/` 的形状识别。

**服务商激活会被并发写覆盖。** 加完服务商、选用、界面却还列着别家的模型——实际对话走的是新
服务商,模型选择器显示的是旧的。`providers.json` 的每次读-改-写都没有锁:激活写入 `activeId`
的同时,一个并发的重排序用它读取时的旧副本回写,把 `activeId` 抹了回去。写入本身是原子的
(临时文件 + rename),所以文件从不损坏——这正是它一直没被发现的原因。

## 变化

**Windows 默认安装目录改为 `...\sdx-aiagent`**(原先是 `...\AI Agent SDX`)。已有安装升级时
不会被搬走,`/D=` 指定的路径依然优先。

**界面不再把 agent 叫作 "Claude"。** 五个语言包共 163 处:空状态、聊天框占位符、
Computer Use 的全部风险说明、权限模式描述。接千问或 DeepSeek 时,"Claude 已准备好帮你构建"
是错的。指向 Anthropic 服务的地方保留原样——「Claude 官方」服务商、Claude.ai 登录、
`~/.claude` 目录。

## 构建

**macOS 构建不再因 Apple 时间戳服务抖动而整个失败。** 之前连续三次构建死在
"The timestamp service is not available",每次都在不同的签名步骤。electron-builder 一次要签
约 33 个二进制,第一个失败就放弃整个构建,而那在依赖内部,改我们自己的脚本够不着。现在是
PATH 上的 `codesign` 包装,所有调用方都获得重试。只重试时间戳失败——身份错之类每次都一样,
重试只会把清楚的报错拖慢四分钟。

**本地构建脚本现在强制 bun 版本。** `packageManager` 钉的 1.3.14 是承重的(1.4.2 会让
`systemProxyBridge` 竞态测试失败),但没有任何地方检查它。而 `brew install bun` 装的版本
PATH 优先级更高——本仓库此前**每一个** macOS 产物用的都是错的 bun,而且构建照样成功。
