# Brand assets

Everything SDX draws of itself comes from one shape. This is where that shape
lives, how it turns into the files each platform wants, and which decisions are
load-bearing rather than taste.

## The mark

A four-point blade-star, taken from the `X` of the SDX wordmark: two tapered
spikes crossing at a shared waist, a long pair swept about 38 degrees off
horizontal and a shorter pair crossing it the other way.

| | |
| --- | --- |
| Component | `desktop/src/components/composite/BrandSeal.tsx` |
| Geometry generator | `desktop/src/components/composite/brandSeal.geometry.py` |
| Tests | `desktop/src/components/composite/BrandSeal.test.tsx` |

The component is the single source of truth. The path data is generated by the
Python script and pasted in, so arm length, lean, thickness and taper are
parameters someone can re-run rather than coordinates they have to
reverse-engineer. Re-running it prints the measured ink bounds, which are what
the component's `viewBox` values are.

Three things about it are deliberate:

**The asymmetry is the point.** An even, axis-aligned four-point star is the
generic "AI sparkle" a dozen other tools already ship. The unequal arms and the
lean off 45 degrees are what keep this one telling them apart.

**Everything is filled, never stroked.** A stroke carries one width along its
whole length and cannot taper, so a stroke thin enough to look right at 80px has
already vanished at 24px. The narrowest feature in the filled version measures
7.57px at the 24px rendering.

**The colour split is load-bearing.** The long blade takes `--color-brand` and
the short one `--color-text-primary`. When a palette lands those two close
together the blades merge into one solid star rather than half the silhouette
dropping out, so the near-monochrome case is a non-event instead of a failure.

A spark at the crossing, which the source artwork has, was tried and cut. Drawn
in ink over the brand-coloured blade it reads as a flash on a dark theme and as
a punched hole on a light one, and an element whose meaning inverts between
themes is worse than no element.

## The app icon

```bash
bun run gen:brand-assets
```

Run from `desktop/`. The generator is `desktop/scripts/generate-brand-assets.ts`.
It parses the blade paths straight out of `BrandSeal.tsx` rather than keeping a
second copy of them, which is the one failure the raster icons it replaced
actually had: the mark could be re-tuned and the Dock would keep showing the old
artwork indefinitely, with nothing failing.

Two deliberate differences from the in-app mark:

- **No sparks.** `BrandSeal` draws them only at `xl` (80px), because below that
  they are under 2px across and read as dirt. An icon is seen mostly at 32–128px
  in a Dock or a taskbar, so they would be dirt nearly everywhere it appears.
  Dropping them also means one artwork at every size, so the mark does not
  visibly jump scale when a Finder window's icon slider crosses a boundary.
- **A frozen palette, and the dark plate.** An `.icns` has no theme to read, so
  the hex is baked in. The dark plate wins on measurement, not preference: at
  16px the light plate's near-black blade sinks into the terracotta one and the
  whole tile goes to mud, while cream-on-near-black still resolves as a star.
  The worst case for each is a matching taskbar — and a dark plate on a dark
  taskbar keeps a legible mark, where a light plate on a light one does not.

| | plate | ink (short blade) | brand (long blade) |
| --- | --- | --- | --- |
| dark — shipped | `#201D17` | `#EDE6D6` | `#D07B52` |
| light — docs only | `#F6F0E1` | `#251E11` | `#96442B` |

The plate keeps the footprint of the icon it replaced (`x=88 y=88 848×848 r=175`
in a 1024 box) so it carries the same visual weight in a Dock. The mark spans
72% of the plate's width.

### What gets written

| Path | Consumer |
| --- | --- |
| `desktop/src-tauri/icons/icon.icns` | `mac.icon` |
| `desktop/src-tauri/icons/icon.ico` | `win.icon`, and the NSIS installer |
| `desktop/src-tauri/icons/icon.png` | the Windows/Linux tray, via `electron/services/tray.ts` |
| `desktop/src-tauri/icons/{32,64,128,256,512}x*.png` | `linux.icon`, which is a directory scan |
| `desktop/src-tauri/icons/128x128@2x.png` | that same scan, and `tauri.conf.json` |
| `desktop/public/app-icon.png` | the H5 favicon (`desktop/index.html`) and the default profile avatar (`src/pages/ActivitySettings.tsx`) |
| `docs/images/app-icon.webp` | the site: its favicon, `SiteHeader.jsx`, and `HomePage.jsx` |
| `docs/images/logo-horizontal{,-dark}.{svg,webp}` | the wordmark lockup; no consumer in-tree today |
| `docs/images/banner.{svg,webp}` | the wide 3:1 card; no consumer in-tree today |
| `docs/public/images/banner.{svg,png}` | `og:image` in `site/index.html` |

Four paths are written that nothing currently reads: `desktop/public/app-icon.svg`,
`desktop/src-tauri/app-icon*.{png,svg}`, and the `-light` / `-dark` variants under
`docs/images/`. They are regenerated anyway rather than deleted, for two different
reasons. `src-tauri/app-icon.png` is pinned byte-identical to its `public/` twin by
`icon-assets.test.ts` — it was the input the `tauri icon` CLI read, never something
`tauri.conf.json` referenced, and this generator has taken over that job. The rest are
masters: the light plate is rendered nowhere else, and a vector that is generated cannot
drift from one that is not.

There is no colour-scheme switching anywhere in the docs. All three site references are
unconditional `<img src>`, so `docs/images/app-icon.webp` is the one the site actually
shows, and `-light` / `-dark` are reference material rather than a fallback pair.

`icon.icns` is built with `iconutil`, which is macOS-only. It is the only tool
here that emits the 16px and 32px ARGB entries a non-Retina display falls back
to; the cross-platform alternatives start at 32px and leave macOS to downscale.

`icon.ico` is assembled by hand, by `buildIco()`. Every off-the-shelf converter
reachable from this repo collapses the file to a single 256px entry and leaves
Explorer and the taskbar to downscale 256 → 16 themselves. The generator writes
all seven sizes Windows asks for (16/24/32/48/64/128/256), matching the layout
the previous icon already used.

### Nothing else may live in `src-tauri/icons/`

`linux.icon` points electron-builder at the whole directory, and it keeps any
file whose name parses as `NxN`. That is a wider net than it looks: the Tauri
shell's `Square310x310Logo.png` once won that scan outright and shipped a
Windows Store tile as the Linux app icon. The Store tiles and the `android/`
and `ios/` icon sets were deleted rather than regenerated — nothing built them,
and because `"src-tauri/icons/**"` is in the packager's `files` list they were
shipping inside `app.asar` carrying the previous product's artwork.
`desktop/icon-assets.test.ts` now fails on any unexpected entry.

## The wordmark

The same generator writes three text-bearing assets: a horizontal lockup in both
plates, a wide 3:1 card, and the 1.91:1 card social scrapers crop to.

The lockup they replace read "Claude Code / Haha" over two lines with a pair of
decorative rules, one of them in a green that exists nowhere else in the palette.
A three-letter name does not need two lines, so this is mark, gap, wordmark, with
one accent rule under the type.

The text is live rather than outlined, which is how the previous set worked too,
so it renders with whatever the viewer has from the font stack. That has one
consequence worth knowing: SVG cannot measure text, so the accent rule's length is
computed from the type size at roughly `0.72em` per glyph rather than from the
glyphs themselves. A few percent of error moves the rule a few pixels. The
alternative — the hard-coded length the previous set used — drifts visibly the
moment anything about the type changes.

### Where the site lives

The fork inherited a custom domain at an apex: `docs/public/CNAME` claimed
`cchaha.ai`, and `SITE_ORIGIN`, the `og:image`, both READMEs and the issue
template all pointed at it. None of that could be repointed, because this account
does not own the domain — GitHub Pages would have refused to claim it, and until
then a social preview of an SDX link fetched the previous project's card from the
previous project's server.

It now publishes as a GitHub Pages **project site** at
`https://berlee-max.github.io/SDX/`. That is a path prefix on a shared origin
rather than a domain, which is the whole of the difference:

| | |
| --- | --- |
| `site/src/lib/siteUrl.js` | the one definition of origin and base; `siteUrl(route)` is what everything else calls |
| `site/vite.config.js` | `base: '/SDX/'` — duplicated, because Vite reads its config before it can load anything |
| `site/index.html` | reads the prefix from `%BASE_URL%`; `og:image` and the favicon are absolute under it |
| `site/src/App.jsx` | strips the prefix before matching a route, or every page 404s |
| `site/src/lib/locale.js` | the root check compares against the base, not against `''` |
| `site/scripts/prepare-static-output.mjs` | canonical, hreflang, `og:url`, sitemap and `robots.txt` all go through `siteUrl` |

`docs/public/CNAME` was deleted rather than repointed, and the guard that used to
assert its contents is inverted: `prepare-static-output.mjs` now fails if a
`CNAME` reappears in `dist/`.

Two things went with it. The site's GitHub icon, its Download button and the
`git clone` line on the home page all still pointed at the upstream repository —
so the download button on SDX's own home page fetched the other project's
releases. And `index.html` carried the upstream's Google Analytics property, which
would have reported this fork's traffic into someone else's account; the tag is
removed rather than replaced.

GitHub Pages is still switched off for this repository, which is why every
`Deploy React Site` run has failed since it was created. Turning it on in the
repository settings is the remaining step, and nothing else needs to change.

## Source artwork

`desktop/src/assets/brand/sdx-logo-source.webp` is the artwork the mark was
derived from. It is kept for provenance and is not shipped — nothing imports it.
Its own palette (black and red) was not carried over: the app's accent already
exists as `--color-brand`, and an icon that ignored it would be the only surface
in the product that did.
